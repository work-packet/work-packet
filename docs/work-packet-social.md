# Making Work Packets Social
- Always a federated network
- Need mechanisms for nodes to publish their existence
- Need mechanisms for nodes to connect
- "worker social network"

- Connect to existing channels
  - Mail
  - Github issues
  - Gist?
  - Confluence
  - Teams (?)
- 

- Goals: 
  - Make easy to move work packets across users
  - Make it easy and safe to share information and raise questions
  - Make it easy and safe for agents to discover and search shared information
    - Efficient information sharing
      - Support creating index snapshots for fast local searching
      - Support sending 'question pings'
    - Must avoid burdening the listener agent with too many tokens
      - Maybe make opt-in
      - Maybe make a batch operation: review incoming, assess, update
  - Maximize "AI connected to social network"
  - Connect to existing channels instead of inventing our own (for the most part)
    - Reduces overhead
    - Increases security
  - Must work well inside an organization as well as publicly
  - Needs a built-in social aspect
    - Suggest activity posts based on what packets get attention
  - Suggest priorities based on incoming work (eg from Issues)
